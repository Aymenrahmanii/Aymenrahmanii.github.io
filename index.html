Computer visionInternship · Jun–Aug 2026

Dual-engine PCB defect inspection at Supra Tech

An automated optical inspection system for printed circuit boards: a supervised detector for known defects plus an unsupervised model that flags anything new.

  • RT-DETR-L retrained for micro-defects, plus PatchCore anomaly detection for unseen scratches and stains.
  • Replaced CIoU with an EIoU + NWD box loss: mAP50:95 rose from 53.6% to 77.8%, with tighter boxes (mAP75 +6.7 pts).
  • SIFT + RANSAC alignment to a golden template, EMA tracking to remove jitter, and Eigen-CAM heatmaps for operators.
  • Served in real time at 30 FPS through ONNX and a FastAPI service (REST + WebSocket).

LLMs & RAGPersonal project · 2026

Regulatory RAG assistant with a real evaluation harness

A question-answering assistant over GDPR, the EU AI Act, NIS2 and DORA that answers with article-level citations, and a test harness that measures every change.

  • Hybrid retrieval: dense embeddings + BM25 fused with RRF, then a cross-encoder reranker.
  • 50 hand-written questions scored on Recall@k, MRR, faithfulness, false refusals and latency, with every run saved and logged.
  • Best setup: Recall@5 0.94, MRR 0.95, faithfulness 1.00, false refusals 0.02.
  • Cloud version on Azure AI Search with keyless auth (Entra ID); infrastructure in Terraform; metric code unit-tested.

MLOpsTeam project · 2026

Security & Quality release gate for an MLOps pipeline

My agent in a 6-person autonomous DevOps/MLOps platform: it collects every quality and security signal for a release and returns one decision.

  • Tests + coverage, lint (ruff), dependency audit (pip-audit), secrets (Gitleaks) and CVEs (Trivy) merged into an ALLOW / WARN / BLOCK verdict.
  • Runs in GitHub Actions CI and is exposed as an MCP server so other agents can query it; optional LLM rationale.
  • Applied to a fraud-detection service with an MLflow model registry, a FastAPI API with Prometheus metrics, and Kubernetes manifests.
GitHub ActionspytestTrivyGitleaksMCPMLflowDocker
Source code

Built on an open-source fraud-detection project by Mohit Gupta; my contribution is the release gate, its tests, the CI and the Docker hardening.

How the gate decides

  • BLOCK · failing tests, a leaked secret or a critical CVE
  • WARN · coverage drop, lint issues or medium CVEs
  • ALLOW · every check green

The same idea maps to model promotion: a new model version ships only when its validation checks pass.
